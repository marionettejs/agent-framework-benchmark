# Methodology

## Defined dataset and task

Four published Marionette **5.1.0** applications are compared with four retained applications for each of Vanilla, React Router, SvelteKit, Nuxt and Angular. The fixed task is the inherited Pokédex `template/SPEC.md` and its 54 independent tests. Every app's `agent/prompt.txt` records the framework task prompt. Marionette's prompt is neutral: “Implement the app described in SPEC.md using Marionette with Vite. Use the latest stable version. Work autonomously until `npm test` passes.” No required Application/CollectionView architecture or router use was added.

The base harness commit is `b95ada03930ca3670c8ff6377c3af815df0ac040`. The inherited `bench`, `template`, `gold`, package metadata and harness history are unchanged by this results publication. The Codex adapter and measurement delta are provided under `harness/`; the inherited Claude-oriented launcher alone is not the adapter used for these apps.

## Generation and accounting

Codex CLI **0.166.0**, Node **24.22.1**, selected model **gpt-6.1-sol**, with reasoning effort and service-tier overrides unset. These are native-default settings, not a verified high-effort comparison. Native metadata reports `explicitRequestOnly` multi-agent mode. An unset web-search override is different from an observed search call. Each Marionette app had a fresh HOME and ephemeral native thread, the version-matched bundled repository skill, built-in system skills and the explicit hosted Marionette MCP server. Unrelated plugins/cloud skills were not exposed in its recorded session.

The exact timing field for **all 24 apps** is `native-session-result.json elapsed_seconds`: the adapter starts its monotonic timer immediately before `turn/start` and stops on the root `turn/completed` notification. This includes agent tool work and self-tests within the turn. It excludes CLI startup, account/config/tooling preflight, app-server close/output drain, independent acceptance and Lighthouse. Receipt ISO `finishedAt` is recorded after shutdown, so ISO timestamp subtraction is not the reported duration. Every published `agent/native-timing-usage.json` retains the exact native interval, start/finish timestamps and root usage; `run-info.json`, `summary.json`, CSV and report use that same interval.

Usage is the final cumulative root snapshot, not a sum of update events. Cached input is a subset of total input; uncached = input − cached. Reasoning detail is not added to output again. Cache-write counters are retained as reported. Root/child aggregation is not generalized to arbitrary spawned agents. Provider request count and actual ChatGPT subscription/credit debit are unavailable. Dollar fields remain null; no API-equivalent amount is asserted. The first-party subscription route was checked privately; account identifiers, credentials and status payloads are not distributed.

## Versions, tooling and hosted identity

All four Marionette apps installed **Marionette 5.1.0, @mnjs/html 1.0.0 and Vite 8.3.8**. Core source revision: `86ee0599ee9c3e1ae472d7426fc3769bd66bdcbe`. Core archive SHA-256: `54cd2784349fac372968b30e7b87584d324e0ba0b306f3d1d14e7e7b3c5745ee`. The bundled skill hash and same-session tool inventory are recorded. Optional companion packages were available without forcing use.

The hosted catalog was 5.0.0 for b1 and 5.1.0 for b2–b4. Both `x-marionette-revision` and `corpusSha256` changed between b1 and b2, and this is an explicit comparability flag. Each slot's recorded before/after identity was stable. No deployment freeze was enforced. Seven tools were advertised; no agent MCP-tool invocation was observed in these four streams. Controller catalog probes are distinct from agent invocation. Tool advertisement/capabilities are indirect handshake evidence, not a wire capture. Zero invocation does not prove identical exposure or no effect.

Collection dates and package versions differ between frameworks. The Marionette agent publication cutoff was `2026-11-12T18:53:25Z` to admit the release; exact installed versions are in per-build receipts and lockfiles. Publication copies replace only local archive dependency references with exact public registry versions/URLs, after verifying the same integrity values; original private lockfiles remain intact. `publication-adaptations.json` and each source manifest disclose these metadata translations. Application implementation files are unchanged. The translated manifests were not used for the recorded measurements and no new app install/benchmark was run for this publication.

## Containment, resource limits and seriality

Generation, independent acceptance and measurement were serial in dedicated rootless Podman containers with actual cgroup limits **4 CPUs / 8 GiB**. Generation timeout: **240 minutes**. The VM provided six CPUs and about 10 GiB RAM. The inner Codex sandbox was disabled only inside the approved unprivileged outer container, without extra capabilities or host-project mounts. Generated commands could reach their own agent session within that container; fresh HOME does not prove sibling credential stores inaccessible. User-owned subscription provisioning is not distributed.

The controller used one serial owner/lock, checked AC power and free space (Mac ≥10 GiB; VM ≥8 GiB) before admission, recorded model acknowledgement, and advanced only after evidence export and verified contained workload exit. Containers were identified by exact ID and matching start epoch for lifecycle actions. Only owned regenerable node_modules/build output was cleaned after capture. The final VM state was verified stopped. No live controller or account setup is invoked by this publication.

## Independent correctness and measurement

Independent acceptance used the pristine 54-test base fixture with only the saved app supplied; each published primary result is 54/54, with unchanged assertions. The source snapshot followed generation and preceded independent acceptance/measurement; the agent may already have built, so strict pre-build provenance is not asserted.

Measurement used Caddy **HTTPS/HTTP2**, Lighthouse **13.5.0**, Playwright **1.64.1**, Linux ARM64 system Chromium **156**, and five samples for each of six routes. The measurement image ID was `d879a3a883786952523294613e963a29ec571ea300aec0f4d6900c5c37e47f9d`; base image ID `6c68e3ae64a6f3d156096926086ddb3572b877fb25706dae2fad489481361a51`; generation image ID `3106de0943b1d306462d647d478feb4678d02f0a937f8e5ce2e4a22c12d76b7b`. These are recorded local image identities, not claims that registry pulls can retrieve them. Distribution package repositories were not fully frozen, so rebuilding is not promised bit-identical.

The API is the fixture's local data mirror rather than live public PokéAPI response timing. Mobile emulation and simulated throttling are retained in detailed reports: 412 × 823 CSS pixels, device scale factor 1.75, 150 ms simulated RTT and CPU slowdown multiplier 4. LCP/TBT are Lighthouse simulated metrics. The fresh measurement container trusted its own generated Caddy public root through a disposable NSS store; no host trust modification or certificate-error bypass was used. The patch preserves certificate and hostname verification. The inherited Chromium no-sandbox execution is confined to the outer disposable container.

The timed command was `node /home/agent/bench/measure.mjs /repo/app /results --runs 5` in a 4 CPU / 8 GiB container. Marionette and retained Nuxt b3 use explicit `api.localhost:127.0.0.1` container-host mapping; not every peer measurement has identical hostname configuration. Nuxt b3's measurement deadline was 3,600 seconds; Marionette used 900 seconds. A deadline caps execution rather than changing individual Lighthouse throttling. Numeric route samples are retained without changing their values. Detailed JSON is a curated copy with image payloads and private identifiers/paths omitted; original private evidence is unchanged.

## Statistics and source size

One app contributes its five-sample median per route. Across four apps, report the median and min/max of those app medians; do not treat 20 route samples as 20 independent apps or combine strongest metrics across apps. Accessibility 100 is an automated score, not comprehensive accessibility proof. Four apps and shared-host/model variation limit causal conclusions; this is not a contemporaneously randomized test of intrinsic framework overhead.

Normalized source uses one explicit pinned formatter policy: Prettier 3.9.10, prettier-plugin-svelte 4.1.1 and Svelte 5.57.3, formatting to a fixed point with explicit options and parser mapping, without app configuration/plugins. It excludes generated roots, tests/fixtures, manifests/locks, assets, dependencies and supplied design CSS. Count nonempty trimmed LF-separated physical lines, including comments. SvelteKit b2 is **946** source-only normalized lines; **69** formatted lines of supplied tokens.css are excluded. All 221 selected original and normalized file hashes were checked. This publication validates supplied formatter results without running an app or new benchmark. See `analysis/loc` for the tool lock, policy, inputs, outputs and per-file metrics. Physical LOC is not complexity or maintainability.
